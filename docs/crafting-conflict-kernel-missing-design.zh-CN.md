# 通用多级合成冲突求解与 Missing 选择

## 文档状态

- 状态：已在 `feature/generic-conflict-solver` 工作树实现，尚未合并。
- 适用模块：`CraftPlannerV2`、`CpSatPlanningEngine`、`CpSatRankedFlowSolver`、`FastCraftingPlanner`、`ReusableStockMatcher`、`PlanningDiagnostics`。
- 本实现不改变 AE2 的合成执行语义，也不修改 AE2 自身的计算线程池。局部精确路径不支持时会回到原有分配修复和有界递归；整张可达图超过统一安全上限时则直接返回保守 Missing，不再进入 AE2 的高成本模拟器。

## 目标与约束

1. 普通确定性 DAG 继续使用一次聚合传播，复杂度保持 `O(V+E)`。
2. 请求数量 `Q` 只作为整数系数参与运算，任何路径都不得枚举 `0..Q`。
3. 多级路线竞争由同一个图模型处理，不识别物品名、配方名、层级名或递推式。
4. 只有精确证明才能提前返回不可行；启发式结果不能伪装成证明。
5. 精确求解受图宽度、矩阵规模、分支节点、单纯形 pivot 和现有搜索预算共同限制。
6. 精确路径耗尽预算或遇到不支持语义时，无损回到原有规划器；整图、模糊宿主矩阵等外层安全上限只允许产生假阴性 Missing，不允许产生假阳性可行计划。
7. Missing 必须来自一条具体路线并继续传导到原料叶子，不能合并互斥路线的缺口。
8. AE2 的 `CRAFT_LESS` 数量探测属于同一次 calculation：图编译和全部重预算只能建立一次，不能按 `O(log Q)` 次探测刷新。

明确禁止以下生产特判：

- `isFibonacci` 一类图形识别；
- 匹配 `x0/x1`、物品注册名或样板来源字符串；
- 为固定层数、固定系数或某个测试类单独选择算法；
- 按请求份数展开状态。

Fib 和各种系数变形只作为测试形状。

## 为什么只在局部使用精确求解

单个样板只有一个主产物，并不自动保证整个规划问题是 `O(V+E)`。同一产物的多条样板、共享库存和整数批次会把不同层的路线选择耦合起来。一般整数可行性仍可能是 NP 难的，因此生产实现采用：

```text
普通线性快路径
    -> O(V+E) 冲突分量发现
    -> 通用不可行上界证明
    -> 各小宽度、小矩阵分量独立求精确整数流
    -> 普通分量线性回放，含启动/顺序状态的分量严格递归回放
    -> 只解除回放失败的局部分量，宽分量继续原有有界修复/递归回退
```

这不是把一般问题宣称为多项式问题，而是让 Minecraft 中常见的小冲突核得到精确处理，同时给刻意构造的实例设置硬上限。

### 一次 calculation 的生命周期

AE2 的 `CRAFT_LESS` 会先尝试完整数量，再按二进制位探测较小数量。同一个请求 `Q` 最多产生 `O(log Q)` 次 `runCraftAttempt`，但这些不是独立规划任务。`CraftingCalculationMixin` 因此为一次 `run()` 创建一个单线程 `CalculationSession`：

- AE2 库存/样板只导出成一张 `CraftGraph`；后续数量探测复用它；
- 每种切环定向的 `PreparedGraph`、可达工作量和副产物稳定顺序只编译一次；
- 精确有理数单元、搜索、状态解析和确定性 fallback 预算由所有数量探测共同消费，并统一服从 attempt 墙钟；
- calculation 返回后立即丢弃 session，不跨请求缓存库存或样板；
- session 绑定创建它的线程，误跨线程使用会直接拒绝；不同 calculation 各有独立 session，仍可并行。

因此 `Q` 的位数仍可能决定 AE2 发起多少次便宜的数量验证，但不能把结构工作预算或整图编译成本乘上 `log Q`。例如完整请求 1024 不可行、库存最多支持 1023 时，第一次重探测耗完精确工作预算后，后续 768…1023 只复用已编译图并走安全回放；所有探测始终位于同一个 3 s attempt 墙钟内。

## 实际算法流程

### 1. 原有线性聚合快路径

规划器先运行 `linearPass`：

- 使用稳定的目标到原料物料流顺序；
- 聚合同一物品的需求；
- 用 `ceilDiv` 一次计算样板执行次数；
- 使用库存并把需求传到输入；
- 已经产生的副产物先于库存和新合成抵扣同物品需求；
- 一次生成完整叶子 Missing。

若图中存在可复用副产物，预处理会为每一种副产物键创建一个临时调度屏障：

```text
所有该副产物生产者 -> 屏障 -> 直接消费者和该物品行
```

同一键无论有多少生产者和消费者都只使用一个屏障，不展开生产者与消费者的笛卡尔积。对这张扩展图做一次 SCC 和稳定拓扑排序；无环时生产者会在消费者执行前进入共享池，未被需求取走的剩余量不会生成新需求，直接丢弃。若该优先关系成环，只放弃环内副产物的线性信用并保留原执行路径，不尝试求“最大无环边子集”。

这项调度是可选优化，默认最多扫描 16384 个样板/输入/副产物单元（`thunderbolt.maxByproductScheduleWork`）。超限时保留原稳定顺序并放弃整张图的副产物前置信用；副产物仍可在严格递归执行中按真实先后使用。该退化可能多报 Missing，但不会把尚未产生的副产物提前消费，也不会产生假可行。

普通、无需种子顺序的线性计划可行时立即返回，不计算分离宽度，也不创建整数矩阵。普通无竞争 DAG，以及能被上述顺序直接解决的普通副产物 DAG，仍为扩展调度图上的线性复杂度。若请求含闭环宏、host-scoped reusable stock 或其他必须先取得种子的状态，线性结果只作为需求/边界基线；即使它在代数上可行，也必须经过严格的“输入先于输出”执行路径才能接受。

### 2. 精确路径的语义门

当前精确模型接收 DFS 已经定向并切环后的局部 DAG，并要求整个请求至少有两个真实竞争产物。只有“整个请求只有一个局部竞争产物”会跳过整个精确路径；某处存在 `seedOrdered` 状态或 `cutOutputs` 不再全局关闭其他局部分量。

以下状态按受影响分量处理：

- 无限复用 returned input：加入一次性启动变量和共享种子储备；
- host-scoped reusable stock：加入逻辑池容量及物理宿主总容量约束；
- 容器 remainder：普通消耗和显式副产物继续进入质量平衡，但结果必须严格回放；
- 副产物生产者到消费者的优先关系位于同一个 SCC：不把这项环内副产物信用写入矩阵，只允许严格回放验证可行向量；
- core 层仍出现有限次数 returned input：该分量跳过精确模型。生产适配层已经把耐久链缩成普通 use-currency 边；core 不再重复实现 `ceil(x/uses)` 特判。

带启动、容器、私有宿主或顺序不安全副产物的矩阵结果只是候选，不提供提前不可行证明。候选会带固定执行次数进入原有递归执行器；若真实种子取得、模糊宿主最大流、输入顺序或副产物顺序不成立，只解除这些有状态分量，再用原有有界递归重算。独立普通分量仍可保留其精确结果。

普通无环副产物不会触发语义门。它既作为物品约束行的正供给系数连接相关决策锥，也参与稳定执行顺序；与任何需求无关的副产物不进入活动图，因此不会影响独立冲突核。

最后一项保留了单局部岔路已经稳定的原搜索语义。只要整个请求有多个真实决策，拆分后的某个独立分量可以只含一个决策；这正是“多个独立小冲突核”需要的行为。以上都是图结构或执行语义条件，不是测试图特判。

### 3. 冲突分量与稳定分离宽度上界

先给每个真实竞争产物分配一个并查集节点，再按稳定逆拓扑序传播“所属决策锥”：

1. 父决策的依赖锥遇到子决策时合并；
2. 两个决策锥触及同一个物品/库存约束行时合并；
3. 仅仅被同一个确定性父样板请求，不会合并；
4. 最后把所属物品和样板按并查集根分组。

因此，不同 AE2 网络本来就不会进入同一张图；即使在同一请求图中，确定性根同时需要两个互不共享资源的竞争子图，它们也仍是两个分量。只有共享决策依赖或共享库存确实产生耦合时才合并。发现与合并总计为 `O(V+E)`，没有枚举分区。

随后在每个分量内部复用已经存在的稳定逆拓扑序。扫描一个产物时：

1. 从活动边界删除该产物；
2. 把它所有样板的普通输入加入边界；
3. 记录边界集合的峰值。

得到的是该固定顺序下可复现的分量内 `separatorWidth` 上界，不计算最优树宽，不运行 `min-fill` 或图同构。所有分量的边界维护合计仍为 `O(V+E)`。

门限也按分量判断。假设三个独立分量宽度为 `[16, 8, 8]`，宽 16 的分量单独跳过精确求解，两个宽 8 的分量照常求解；不会因为全局最大值为 16 而把两个 8 一起拒绝。`separatorWidthPeak` 仍记录所有分量中的最大值，所以该例诊断值为 16。

### 4. 乐观容量不可行证明

在逆拓扑方向为每个物品计算：

```text
optimistic[item]
    = stock[item]
    + sum(每条样板在其各输入 optimistic 容量下可生产的数量)
```

这里故意把不同路线、不同父节点对同一库存的使用重复计算，因此结果只能偏大，不能偏小。

所以：

```text
optimistic[target] < requested
```

是严格的不可行证明。相反，`optimistic >= requested` 只表示“尚未证明不可行”，不能当作可行结果。

每个输入的容量通过 `CraftInput.firingsFrom(available)` 计算，因此普通输入按每次消耗计数，无限复用催化剂只要求一次种子，有限耐久工具按可用次数计数。该证明是额外一次 `O(V+E)` 扫描。无库存的多层两路线递推在这里直接结束，同时保留 `linearPass` 已经传到基础叶子的 Missing，不进入递归，也不创建整数节点。

若活动图含可复用或顺序不安全的副产物，或整个请求要求种子顺序，则当前实现不使用这项容量证明：忽略副产物或一次性启动状态可能把真实上界算小，不能作为不可行证据。切环图只证明当前定向；外层仍可按既有上限尝试其他允许的环定向。

### 5. 通用整数流模型

容量证明不能决定时，对每个满足门限的冲突分量分别建模。分量内每个样板创建一个非负整数变量 `x_p`，表示样板执行次数；每个分量物品创建一条质量守恒不等式：

```text
sum(生产 item 的 outputAmount * x_p)
+ sum(产生 item 的可复用 byproductAmount * x_p)
- sum(消耗 item 的 inputAmount * x_p)
>= externalDemand[item] - stock[item] - externalSupply[item]
```

`externalDemand` 是分量外确定性前缀对该分量入口的固定需求；若目标本身位于该分量，还包含目标请求数量。`externalSupply` 是分量外已固定样板给该分量产生的副产物。分量内样板的消耗和副产物已经在矩阵左侧，不会重复计入。约束保持 `>=`，所以多余副产物只是松弛量，不要求后续消费。并加入：

```text
0 <= x_p <= Sat.SAT
x_p 为整数
```

这个矩阵自然保留分量内的多层重新汇合、共享库存和可复用副产物。表面不同的 `A/B` 若最终都消耗 `C`，决策锥会先因同一个 `C` 库存行合并，随后落到同一张矩阵的同一条 `C` 约束中，不会被误当作两个独立库存。

模型不要求 Fib 结构，也不要求系数为 `0/1`。批量输出和不同输入数量直接成为矩阵系数。

无限复用 returned input 不是 `inputAmount*x_p`。对每个含这类输入的样板再创建二元启动变量 `z_p`：

```text
z_p <= x_p <= Sat.SAT * z_p
0 <= z_p <= 1，且 z_p 为整数
```

同一个普通种子键，或同一个 `(key, storageScope, poolScope)` 逻辑宿主池，共享一个一次性储备。设普通网络储备为 `r_g`，host 私有储备为 `h_g`，每个使用该组的样板加入：

```text
r_g + h_g >= requiredAmount * z_p
```

因此同一把工具供多个样板顺序使用时取需求最大值，不按执行次数求和。普通储备在对应物品质量行中只扣一次；若 host 私有种子键根本不在普通可达物品图中，则没有普通消费/生产行，只由下面的启动上界约束它。

启动约束只允许库存、固定边界供给、无环替代主产物和安全副产物支持 `r_g`；任何自身需要同一组种子的样板都不能证明自己的启动条件。这样 `seed -> net +seed` 在没有物理种子时不会凭代数流自启动，而一个独立 `raw -> seed` 样板可以先执行一次再启动宏。

host 侧同时加入两层保守容量：每个逻辑池不能超过其路由接受的物理变体总量，同一 `storageScope` 下所有逻辑池的 host 储备之和不能超过物理宿主快照总量。这仍是模糊分配的松弛；最终是否能同时匹配由现有 `ReusableStockMatcher` 最大流和严格回放决定，矩阵不会取代它。

### 6. 有界精确求解

`BoundedIntegerLinearSolver` 求解：

```text
A*x >= b, 0 <= x <= Sat.SAT, x 为整数
```

实现方式为：

1. 用 `BigInteger` 有理数执行精确 Phase-I simplex，求一个 LP 可行点；
2. 若点为整数，返回可行解；
3. 若某坐标为分数，在 `floor/ceil` 两侧做 branch-and-bound；
4. 整个求解共享分支节点和 simplex pivot 预算；
5. 每次创建 tableau 前按 `rows * columns` 做准入，并对实际扫描、pivot 和坐标最小化累计有理数单元工作量；
6. 同一次 planning attempt 的所有数量探测、局部分量及路线重放共享路由层的墙钟截止点和同一个结构工作预算，不能通过拆成许多小矩阵或重复 `CRAFT_LESS` 探测刷新；
7. 只有分支前沿完整耗尽才能返回 `INFEASIBLE`；
8. 任一预算耗尽返回 `BUDGET_EXHAUSTED`，随后走原规划器，绝不冒充不可行证明。

当前生产门限，均按单个分量判断：

```text
separatorWidth <= 12
样板变量数       <= 96
含启动/储备的总变量数 <= 96
物品约束数       <= 128
整数分支节点     <= 64
全求解 pivot     <= min(1024, max(64, 4*(变量数 + 含上界的约束数)))
单张 tableau     <= 16384 个有理数单元
整次 calculation 精确工作 <= 2097152 个有理数单元操作
局部求解不另切时间片；服从整次 planning attempt 的剩余墙钟（默认总计 3 s）
```

进入求解器之前还会按 `items + patterns + inputEdges + items*patterns` 向现有全局搜索预算收费；最后一项覆盖稠密矩阵初始化成本。显式配置的小预算仍然可以禁止任意分量的这条路径，预算不足的分量单独回退，不影响已经求解的兄弟分量。

tableau 单元数在分配二维数组和转换全部 `BigInteger` 系数之前检查。单张矩阵过大只拒绝该分量，不消耗其他小分量的机会；累计单元工作由整个 calculation 共享。求解循环同时执行候选上下文的截止检查：V2 内建精确核、独立 CP-SAT 引擎、SCC 证明都读取各自候选 attempt 的剩余墙钟，不各自取得 100/250 ms 的新配额。默认总墙钟由 `thunderbolt.planningTimeoutMs=3000` 控制；tableau 形状和工作量仍分别可由 `thunderbolt.maxLowWidthTableauCells`、`thunderbolt.maxLowWidthCellWork` 调整。

V2 的低宽局部核仍是内建 `BoundedIntegerLinearSolver`，不装载或调用 CP-SAT。V2 的分量比较继续采用“分级 Missing、分级 used、执行次数”的既有语义；CP-SAT 的整图目标在下节单独定义，两者不共享 session、整数后端或诊断状态。

### 7. 外层安全上限

局部精确预算不能限制“精确求解之前”的恶意大图，因此还有三层与具体配方形状无关的通用上限：

```text
AE2 -> CraftGraph 导出工作量       <= 65536  (thunderbolt.maxGraphExportWork)
core 可达 item/pattern/input/output <= 65536  (thunderbolt.maxReachablePlanningWork)
reusable route × physical variant   <= 262144 (thunderbolt.maxReusableMatchPairs)
```

第一项在不可变 `CraftGraph` 建立前计数，覆盖 BFS 节点、样板、输出、输入槽、具体模糊模板和实际生成的组合；同一图因耐久/需求语义重建时仍共用一个预算。超限后丢弃部分图并使用空的保守图，所以目标只会显示 Missing。

第二项在任何图归一化前做一次可达扫描，同时把副产物输出计入工作量；一旦超过上限便停止扫描并返回 `budgetExhausted=true` 的目标 Missing，`planRuns=0`。它避免一个数万节点/输出的刻意图在多轮线性预处理中仍占用数秒。

第三项在创建最大流节点和边之前检查潜在笛卡尔矩阵，并另外限制候选迭代次数。超限返回 `feasible=false` 的匹配结果；调用方只能改走其他样板或显示缺少催化剂，绝不会双花一个物理变体。默认 256×256 的全模糊匹配仍完整求解，513×513 会在展开候选前保守退出。

这些是生产安全边界，不是 Fib、物品名或固定层数特判。它们允许极端构造出现假阴性；共同的不变量是：任何超限路径都不能返回未经完整库存/执行校验的 `feasible=true`。

反馈 SCC 的加权非增益位势证明单独限制为最多 32 个状态、64 个内部样板和 512 个整数分支节点；这些是模型形状/工作上限，与请求数量和权重大小无关。32/64 双向素数比例环的本机热态复测为 p50 约 68–70 ms、max 约 70–72 ms，因此 100 ms 是性能目标，不是 cutoff。十亿级长系数压力样本约 154–174 ms，仍可继续使用整次 attempt 的剩余墙钟；33 状态或 65 样板则在整数搜索前保守拒绝。

### 8. 解回放和二次校验

整数解不会直接作为最终结果。普通已解分量的执行次数先合并成固定向量，再按同一稳定拓扑序回放完整请求；未解的宽分量或预算截止分量仍使用原动态容量分配。回放重新计算：

- 每个物品的实际需求；
- 样板产量和批次余量；
- 实际库存用量；
- 所有输入是否都在其产物之后得到处理。

副产物整数模型是质量平衡松弛：它允许丢弃剩余量，但单独看矩阵也可能选择“多做主产物，只为制造副产物”的向量。回放因此还要求每次固定样板执行都能由实际主产物需求证明；批次向上取整产生的余量允许进入共享池，但不能为了副产物额外开启一个主产物批次。若这项检查失败，只解除含副产物分量的固定向量，独立普通分量仍保持固定。

分配修复只能调整未固定分量，不能重选已解小分量的路线。只有混合回放后库存仍满足全部需求，才构造 `feasible=true` 的 `CraftPlan`。未通过完整回放的副产物向量也绝不会成为递归固定配额；递归继续使用自己的严格输入先于输出语义。固定向量若因任何不一致无法覆盖实际边界需求，则相应局部结果作废并安全回到原路径，绝不据此产生假可行或假 Missing。

含启动或其他顺序状态的已解分量不经过上述普通线性接受路径，而是把整数向量作为配额交给现有递归执行器。执行器先处理含无限 returned seed 的宏；如果它需要无环替代样板或已证明的单步反馈 converter 制造启动种子，这些启动执行也会从同一固定配额中扣除，不能在主需求之外凭空多执行。真实 host 借用继续走全局模糊匹配。候选若无法启动，规划器回滚整个候选执行状态，只解除所有要求严格回放的分量，再运行一次原有有界递归；普通精确兄弟不需要重算。

### 9. 独立 CP-SAT 整图模型

配置开启后注册的是独立 `CpSatPlanningEngine`。它只借用 `FastCraftingPlanner` 的 AE2 图导出和计划格式转换，不创建 `CraftPlannerV2.PlanningSession`，也不把 CP-SAT 作为 V2 的局部整数后端。CP-SAT 模型返回 `UNSUPPORTED/UNKNOWN/INVALID` 时该引擎直接 `DECLINE`；多规划器路由随后是否尝试 V2，是候选之间的正常顺序回退，不是 CP-SAT 内部回退或混合求解。

对纯转换或带外部耗材/只读催化剂的守恒转换 SCC，`CpSatRankedFlowSolver` 建立无时间展开的 Bool + group-rank 模型：

```text
x[p] >= 0                                      样板 p 的 long firing 数
active[p] <=> x[p] > 0                         是否选择该样板
active[p] => rank[group(input)] < rank[group(out)]
stock[i] + Σ(produce-consume)*x >= demand[i]    精确终态物料平衡
```

未取得更强证明的物品各自占一个 group，严格 rank 仍使被选择的支持成为 DAG。同时通过 `CycleAnalysis` 精确比例守恒证明和 `ConservativeFeedbackAnalysis` 严格 marked-cycle 证明的转换 SCC 可以共享一个 group；因此 `3A -> 9B; 3B -> A` 这类非单位但等价的转换可以在同一解中同时使用两个方向。多入边、多出边和损耗环不能冒充这种零净转换环，而是进入后述 Petri 宏证明；正增益或未取得非增益证明的活动环仍不放宽。

同 group 不再靠终态平衡猜测可执行性。CP-SAT 先选择 long firing vector；独立重放再把固定向量分成闭式 primitive round 和有界 residual。小 residual 逐 firing 选择已启用转换；发生死锁时显式补入所需最少状态，因此能证明 `A->B, B->A, A->B` 这种必须交错、不能按“每种样板一整块”执行的前缀。大比例或复杂非增长 SCC 使用同一加权位势证明和闭式 canonical prefix，不按请求量建立时间层。每个候选前缀都含精确 `required[state]` 与 `delta[state]`，由独立的 CP-SAT one-hot 选择后真实扣取；任何输入前缀、催化存在量或目标扣除失败都会作废。额外启动缺口会进入最终 Missing，补齐后再次规划必须能执行。

守恒严格环还提供原始零净变化 firing 向量 `primitive[p]`。完整一轮对内部状态净变化为零、对外部普通输入只会额外消耗，所以从任意全部满足 `x[p] >= primitive[p]` 的候选中减去一轮，所有物料下界和同一启动前缀仍成立，且 `Σx` 严格下降。模型据此直接加入：

```text
OR(p in cycle, x[p] < primitive[p])
```

这把“无意义重复转一整圈”作为已证明的支配约束消掉。CP-SAT 的整图目标使用严格词典序：先按“物品沿输入需求边到请求根的最短距离”从近到远逐层最小化 Missing，再最小化 `Σx[p]`，最后最小化全部实际初始库存占用。可证明 `Missing=0` 时先在克隆模型上一次证明零缺口并同时求执行次数，避免深 Fib 为每个空 Missing 层重复求解。每一级最优值都会固定为等式，只有得到 `OPTIMAL` 才接受；辅助 activation、rank、有限耐久批数和催化储备不计入执行次数。

无限 returned 催化物是存在量而不是流量，另加：

```text
active[p] => stock[c] + Σproduce[c]*x >= catalystAmount[p,c]
```

它不乘 `x[p]`、不被扣除，同一催化物可跨样板共享。若同一物品又被普通消耗，只有当所有 catalytic read 都位于同一个已证明反馈宏且该物品是宏状态时才准入：宏先在状态 group 执行，环外普通消费者由 rank 强制排在其后。其他“先催化再消耗”情况仍保守拒绝。有限耐久使用整数变量 `toolBatches = ceil(x[p] / uses)` 并按 `amount * toolBatches` 进入余额；生产适配层遇到同物品逐级损坏时先建立 `DurabilityChain`，把各损坏态库存折成 carrier use 数，完整工具配方则产生一整条链的 use 数，所以 CP-SAT 既能消耗现有残余耐久，也能沿工具主产物配方补造下一件。互不重叠的 host 私有 fuzzy seed 路线以独立物理库存池进入存在量和最终借用明细；物理候选在两个逻辑池之间重叠时仍保守拒绝，避免尚未编码完整二分匹配时双花库存。

`CraftInput.remainder` 不再是特殊的第二套产物流：建立 `CraftPattern` 时会把它规范化成普通副产物 post-arc；旧导出器已经显式声明同键副产物时只保留一次，避免容器翻倍。输入上的 remainder 字段仅保留给 SCC/启动顺序识别。于是 `full -> target + empty; empty + water -> full` 与其他守恒副产物反馈使用同一余额、加权非增益证明和前缀重放；无任何 full/empty 启动态时报告一个真实 seed，补齐该 Missing 后可执行。

普通副产物直接进入 `produced[p][item]` 余额，并额外约束样板 anchor rank 早于其他输出 rank，保证副产物消费者不会排到生产者之前。对 `ConservativeFeedbackAnalysis` 已证明的非增长 SCC——包括 weighted lossy、分支/汇合副产物和内部 returned-catalyst read arc——所有内部状态共用一个 group，但不把请求量展开为时间层：

1. 整图 CP-SAT 先独立求出完整 long firing vector；
2. 若本次实际启用的 SCC 边已经是 DAG，直接按活动边拓扑重放，不收取未启用反向边的启动储备；
3. 若活动边仍成环，证明器把固定 firing vector 分解为闭式 primitive round 加有界 residual，或用已证明加权非增益位势生成保守但可执行的 canonical prefix；
4. 每个 prefix 形成一行 `required[state]` 和 `delta[state]`，独立 CP-SAT 用 ExactlyOne Bool 选择一行，排序仍遵循分级 Missing、总 used；固定 firing vector 的执行次数天然相同；
5. 回放先真实扣取选中启动 marking，再只处理宏的环外输入/输出，最后放回 `required + delta` 内部状态。额外启动缺口会并入 Missing，补齐后重新规划必须可执行。

普通副产物余额还受“主产物需求证明”约束。对主产物批量 `q[p]`，活动样板至少要有 `q[p]*x[p]-(q[p]-1)` 个主产物被目标、其他样板的普通/耐久输入或共享催化存在量真正需要；只允许最后一批自然向上取整的余量被丢弃。这样不能为了多拿副产物而额外执行一次主产物无人需要的样板，同时 `4P+B` 为 `1P+1B` 正常执行一批仍合法。该约束直接写成 firing/activation 的线性式，不增加另一个 long 域辅助变量。

因此反馈宏没有调用 V2，也没有把 CP-SAT firing vector 交给 V2 补全；它只复用独立的 Petri/SCC 证明工具。未证明非增长的活动环仍只能由严格 rank 选择无环方向，`INFEASIBLE/UNKNOWN` 也不会被提升为这类更一般状态网的不可达证明。

OR-Tools 要求全模型所有整数域及线性式范围可安全放入有符号 int64；实现先按 firing 变量数均分域预算，再按每个样板最大化学计量系数继续收紧，使一条包含所有 firing 的物料/主产物行仍不溢出。rank 图默认边界为 256 个物料、192 个样板，不设独立求解毫秒数；每次调用和反馈 prefix one-hot 都使用 CP-SAT 候选 planning attempt 当时的全部剩余墙钟。`SOLVED` 后仍做独立回放：按返回 group-rank和已选 Petri prefix，逐批扣除普通/有限耐久输入、检查催化存在量、分配 host 私有借用、加入产物并最后扣除目标；任何不一致都使 CP-SAT 候选 `DECLINE`。

旧的 Reservoir 阶段模型已移出生产路径。它虽然表达了前缀非负，但只得到“每阶段任意拆分数量 + 终态余额”，没有把 TB 已知的单批执行、方向互斥和拓扑次序直接交给求解器，导致大量阶段拆分对称；8 层交叠转换环会耗尽 30 s，而同一实例的 Bool + rank 只有几十个变量。

## Missing 路线选择

可行计划始终优先于任何 Missing 非空的计划。

V2 跨切环定向的全局比较使用“分级 Missing 最小 > 分级 used 最小 > 执行次数最小”；独立 CP-SAT 使用“分级 Missing 最小 > 执行次数最小 > 总 used 最小”。两套目标互不调用，也不把一个求解器的中间计划交给另一个继续求解。

当所有兄弟样板都无法覆盖剩余需求时，当前实现只对它们“直接共享的普通输入”做展示投影。对每种共享输入分别比较：

```text
(max(0, projectedNeed - available), projectedNeed)
```

候选必须在所有共享输入上不差，并至少一项更好，才替换当前路线；多维不可比时保持稳定样板顺序。路线私有输入只参与容量和最后的叶子 Missing，不混入这一步。

例如：

```text
RA: A + 2C -> D
RB: B + 1C -> D
```

两条都不可行时选择 `RB`，随后输出该具体路线的 `missing B`、`missing C`，不会同时拼入 `missing A`。如果 `RA` 可行而 `RB` 不可行，则仍选择 `RA`。

这个投影只是诊断路线选择，不用于证明性剪枝。多层重新汇合的正确可行性由完整整数流矩阵负责；若精确路径没有得到可行计划，且兄弟样板没有直接共享输入，Missing 展示保持稳定路线顺序。当前实现不维护全局 Pareto Missing 前沿，也不保证一般情况下展示全局最小 Missing。

## Fib 只是宽度 3 的测试形状

测试图每层有两条路线：

```text
R1: X(i-1) + X(i-2) -> Xi
R2: X(i-2) + X(i-3) -> Xi
```

稳定扫描中只需保留连续三个活动物品，因此测得 `separatorWidth=3`。代码没有识别这个递推式：

- 全部物品随机重命名后走相同路径；
- `1/2`、`2/2` 和错位系数组合走相同路径；
- 深度 30、请求 `10^9`、无库存时由乐观容量证明直接返回叶子 Missing；
- 深度 7、请求 `10^9`、只有 `X1/X2` 库存且必须跨层选路时，由一次通用整数流求解得到计划；
- 工作量不按请求份数增长。

无库存证明不受 96 个样板变量门限限制，因为它只做线性扫描。需要精确分配且单个冲突分量超过门限的部分会按设计回到有界搜索；同请求中的其他小分量仍可精确求解。

## 复杂度与上界

设：

- `V/E`：活动合成图的物品和输入边数量；
- `Y`：活动副产物输出、共享屏障及其直接消费边数量；
- `P_i/R_i/A_i`：第 `i` 个进入精确模型分量的样板变量、物品约束和启动/储备辅助变量数量；
- `B_n`：每个分量的整数分支节点预算，当前最多 64；
- `B_p`：每个分量整棵 branch-and-bound 树共享的 simplex pivot 预算，当前最多 1024；
- `B_c`：一次 calculation 共享的有理数单元工作预算，默认 2097152；
- `T_a`：一次 planning attempt 的总墙钟，默认 3 s；各求解阶段只读取剩余值，不做固定分配；
- `L`：AE2 对同一 calculation 发起的数量探测次数；`long` 数量下 `L<=64`；
- `Q`：请求数量。

普通路径：

```text
副产物屏障、SCC、稳定排序       O(V+E+Y)
线性传播                       O(V+E+Y)
额外整数矩阵工作               0
```

多级普通输入冲突图：

```text
分量发现、边界与乐观容量       O(V+E+Y)（并查集附带反 Ackermann 因子）
矩阵构造                       sum O((P_i + A_i) * R_i + E_i + 启动约束数)
精确求解                       每分量受 B_n、B_p、P_i<=96、R_i<=128、tableau<=16384 限制
全部精确分量                   合计受 B_c 和 T_a 限制
数量相关算术                   依赖 O(log Q) 位数，不出现 O(Q) 循环
```

因为分量互不共享库存行与决策依赖，矩阵不会做跨分量笛卡尔积；十个独立宽 3 分量是十张小矩阵，不是一张宽 30 矩阵。全局搜索预算按每张矩阵的稠密单元数收费，限制可尝试分量总量。

同一 calculation 的 AE2 图导出、可达扫描和每个切环定向的图归一化只做一次；每个数量候选仍必须重新执行质量平衡/库存验证，所以最坏为 `O((V+E+Y)*L)` 的有界线性回放。关键区别是矩阵/tableau、搜索和 fallback 重预算不会乘上 `L`，且 `L` 由 `long` 位数固定限制，而不是随 `Q` 数值增长。

一次 dense tableau pivot 的算术槽位数量是矩阵维度的多项式，但 simplex 和整数 branch-and-bound 的理论最坏情况仍可指数增长。这里的生产保证来自硬规模/工作预算和安全回退，而不是声称一般 ILP 已变成多项式算法。

`BigInteger` 保证 LP 判定不受浮点误差影响；系数位数越大，单次整数算术也会更贵，但请求 `long` 不会转化成逐份枚举。

## 线程模型与并行边界

当前依赖的 AE2 19.2.17 已经把每个 `CraftingCalculation` 提交到静态 `Executors.newCachedThreadPool`，线程名为 `AE Crafting Calculator`。本次修改明确不替换、不限制也不重配这个 AE2 执行器。Thunderbolt 只保证自己的状态隔离：`CalculationSession`、`CraftPlannerV2` 可变池、tableau 和分支前沿都属于一个 calculation；不同 calculation 没有共享预算或可变求解状态，可以在不同平台线程上并发。

所有 Thunderbolt 重循环、图导出、SCC/拓扑、模糊最大流和有理数求解都保留退出检查。隔离候选收到外部取消时，候选内部由 `PlanningExitException` 统一要求尽快返回当前最优或 `DECLINE`；路由层仍按 cancel 传播、丢弃返回结果且不进入 AE2 慢路径。未绑定候选上下文的旧路径仍以线程中断和 `CancellationException` 退出。普通运行时异常仍记录上下文后回退，`OutOfMemoryError` 等致命 VM 错误不会被 `catch Throwable` 吞掉后再启动一次高成本计算。

本实现不在单次规划内部再开虚拟线程或并行 branch-and-bound：

- 反例的主要成本是 `BigInteger`/gcd 的 CPU 运算，不是阻塞等待；虚拟线程不会减少计算量或解除 CPU 占用；
- 最危险的反例只有一个耦合分量，无法靠“独立分量并行”拆开；
- 并行搜索 floor/ceil 分支会复制 tableau、增加总内存和无效工作，并使第一个可行解及 Missing 路线的稳定顺序更难保证；
- AE2 的 cached pool 已允许不同请求并行，再增加内部并行会形成嵌套并行，恶意并发请求反而更容易占满全部核心。

未来如果有同一请求包含很多耗时且真正独立的分量，可只对这些分量使用有界的平台线程池，并让所有任务共享同一个截止时间和单元工作预算；不应使用无界线程、公共 `ForkJoinPool` 或按 branch-and-bound 节点创建任务。当前基准下，小分量直接顺序求解更快，先用预算 cutoff 比内部并行更可靠。8 个独立近整数压力任务并发时各自保持独立预算并同时完成，但这只是线程安全验证，不是建议扩大 AE2 的并发度。

## 诊断字段

`PlanningDiagnostics` 新增：

- `separatorWidthPeak`：所有冲突分量中，稳定顺序下测得的最大活动边界；
- `lowWidthAttempts`：实际进入整数求解器的分量数；
- `lowWidthSolved`：得到可行整数向量的分量数；
- `lowWidthInfeasible`：容量证明或完整整数搜索证明不可行的次数；
- `lowWidthCutoffs`：tableau 准入、累计单元工作、期限、整数节点或 pivot 预算耗尽次数；
- `lowWidthIntegerNodes`：访问的 branch-and-bound 节点总数。

旧的公开构造器仍保留；旧调用方未提供的新字段默认取零。

## 回退语义

以下结果都不会破坏原规划，并且只让对应分量放弃精确求解或固定候选：

- 宽度或矩阵超过门限；
- 全局搜索预算不足；
- tableau 单元、累计有理数工作、attempt 墙钟、整数节点或 pivot 预算耗尽；
- 精确算术、矩阵构造或回放发现不支持状态；
- core 层局部分量仍含未归一化的有限耐久 returned input；
- 启动储备、真实模糊宿主分配、容器/副产物顺序无法执行矩阵候选。

图导出、整图可达工作或 reusable 匹配超过外层上限时不会进入上述“局部分量无损回退”，而是直接保守报缺；副产物调度超限则仅放弃提前信用。两者都属于 Policy A：允许刻意极端实例假阴性，不允许假阳性。所有数量探测共用预算，后一个探测看到预算已耗尽也按同一规则退化，不能刷新重算。

已解普通分量在混合线性回放和 allocation repair 中保持固定；若仍进入最终有界递归，递归路径也只消费该分量已证明的剩余样板次数配额，回滚时配额随 trail 一起恢复。含普通无环副产物的向量只有在完整混合回放直接得到可行计划时才会被接受，否则在递归前解除固定。含种子、host、容器或顺序不安全副产物的候选必须经严格递归回放；失败时只解除这些有状态分量并重试，独立普通分量保持固定。以上全部属于 V2 自身。独立 CP-SAT 引擎只接受自身 Bool + rank/余额模型并经自身回放验证的 `SOLVED`；超出准入、超时、模型无效或回放失败一律 `DECLINE`，不进入 V2 内部路径。

## 验收覆盖

1. `Q=10^12` 的固定整数等式在一个 LP 节点内求解，不枚举数量。
2. 分数松弛但整数矛盾的奇偶系统能够证明不可行。
3. 显式一个节点预算时返回 cutoff，不扫描整数域。
4. 随机小型带符号系统与穷举结果一致。
5. 多层两路线递推无库存时 Missing 只落在三个基础叶子。
6. 全物品重命名不改变宽度、路径或 Missing 数量。
7. 四组不同系数使用同一个容量证明。
8. `Q=10^9` 的多层混合路线由一个通用整数流解完成。
9. 乐观容量因共享库存被重复计算时，精确矩阵仍能找到正确替代路线。
10. `A+2C` 与 `B+C` 的不可行展示选择后者；可行路线仍优先。
11. 2000 层普通 DAG 不创建任何低宽度整数工作。
12. 单体活动边界达到 13、但由 11 个独立宽 3 分量组成时，11 个分量全部独立求解。
13. 分量宽度为 `[16, 8, 8]` 时，只跳过 16，两个 8 均进入并完成精确求解。
14. 两个决策锥共享基础库存行时，先合并为一个分量，只进入一次整数求解。
15. 原有全量测试保持通过。
16. 无环副产物先满足兄弟需求，百万级无关剩余量直接丢弃且不形成需求。
17. 副产物信用不能为自身主产物额外开启批次；失败时 Missing 仍传导为真实剩余缺口。
18. 随机反向构造的 3000 张可行图保持可行，副产物松弛向量不能污染递归固定配额。
19. `Q=10^9` 的多层冲突图共用一把无限 returned 工具，工具库存只扣一次且仍由一个局部整数流完成。
20. 自增闭环宏可以由一个无环替代样板先制造种子；没有任何种子来源时，宏不能靠自身输出赢得路线选择。
21. 两个逻辑闭环池共享同一个物理 host 时，总容量约束阻止双花，并由严格模糊匹配回放确认实际分配。
22. 已启动的闭环宏产生的安全副产物可以满足竞争兄弟，未用完的副产物继续丢弃。
23. 一个无关切环分量不会全局关闭另一个低宽度 DAG 分量的精确求解。
24. 超过单张 tableau 门限的矩阵在分配和 branch-and-bound 前返回 cutoff。
25. 24 层共享 returned seed、十亿级近整数批次链在 2 秒回归上限内安全 fallback；修复前同图稳定消耗约 7.8 秒 CPU 时间。
26. 全量规划器和模块构建保持通过，且请求数量仍只影响整数系数位数，不产生逐份循环。
27. `CRAFT_LESS` 的 1024→1023 二进制探测共用一个 session：后续探测复用图编译，且精确预算耗尽后不再创建整数节点。
28. AE2 适配层使用同一个 session 连续规划两个数量时，`getCraftingFor` 调用数在第一次之后不再增加。
29. 14000 路副产物扇出超过整图上限后 `planRuns=0` 并保守返回目标 Missing；25000 路对抗基准由约 3.5 秒降至几十毫秒级。
30. 256×256 全模糊 reusable 匹配仍完整求解；513×513 在候选枚举前保守退出；2000×2000 对抗输入不再创建 400 万条配对边。
31. 外部取消传入隔离候选时抛 `PlanningExitException`，但路由层仍按 cancel 结束且不回落到 AE2 模拟器；未绑定上下文的旧路径继续抛 `CancellationException`。
32. 8 个独立近整数规划并发执行时没有共享状态、串行锁或预算串扰。
