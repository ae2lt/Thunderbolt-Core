# 快速合成规划器能力参考测试

本文只定义作者自行运行、据实声明的参考测试，不参与运行时算法注册、选择或调度，也不要求 Thunderbolt 自动执行测试。测试耗时用于判定是否超过用例时限，不作为算法之间的速度排名。

## 运行

使用 Java 21，在仓库根目录执行：

```shell
./gradlew referenceCapabilityTest
```

每个动态测试都会输出一行 `[reference-capability]`，包含用例、能力族、材料模式、规模、分类、缺失量倍率、缺失集合和耗时。完整结果也保存在 Gradle/JUnit 测试报告中。

作者只有在自己的生产入口执行该用例并得到 `SUPPORTED` 时，才能声明支持该能力。不能用绕过生产入口的专用测试实现代替声明依据。

## 结果分类

| 分类 | 含义 | 可声明支持 |
| --- | --- | --- |
| `SUPPORTED` | `check` 接受，实际规划完成，且结果通过语义校验 | 是 |
| `CHECK_REJECTED` | `check` 已知该请求不支持，诊断执行也未证明是假阴性 | 否，安全的早期拒绝 |
| `ATTEMPT_DECLINED` | `check` 接受，但实际规划主动返回不支持 | 否，安全的晚期拒绝 |
| `FALSE_NEGATIVE` | 生产路径被 `check` 拒绝，但诊断强制执行能正确完成 | 否，但不会让错误计划进入执行阶段 |
| `ENGINE_ERROR` | `check` 或规划抛出异常 | 否，且算法不知道或未正确表达边界 |
| `ENGINE_TIMEOUT` | 超时后能响应中断并退出 | 否，且算法不知道或未正确表达边界 |
| `NON_COOPERATIVE_TIMEOUT` | 超时后在宽限期内仍不响应中断 | 否，风险高于普通超时 |
| `FALSE_POSITIVE` | 生产路径接受并返回，但可行性、缺失量或计划语义错误 | 否，可能把错误计划交给玩家或机器 |

只有 `SUPPORTED` 是真正支持。`DECLINE`、异常、超时、假阳性和假阴性必须分开保留，便于 UI 给出不同反馈，也便于作者修正能力声明。

## 三种材料模式

每个能力用例独立运行三次：

1. `MISSING`：材料不足。结果必须正确判定不可行，缺失项不能少报或报错种类；允许多报，但记录 `missingOverhead = 实际报告缺失成本 / 最小有效缺失成本`。有多组等价最小解时取可匹配解中的最低倍率。
2. `MINIMUM`：只给足一组最低可行材料。通常必须搜索出正确可行计划。自增环是明确例外：不要求完成增殖，只要求安全裁掉自回边、不得产生该配方的 firing，并如实报告裁切后仍缺少的数量。
3. `UNBOUNDED`：所有叶子材料近似无限。必须搜索出正确可行计划。

倍率只评价缺失报告质量，不用于规划器优先级或速度排序。

## 参考能力集

当前套件共 11 个图族、33 个材料用例：

- 单配方 DAG：分散树 `A <- B+C, B <- D+E, C <- F+G`；深度 32 的单配方 Fibonacci DAG。
- 多配方 DAG：会诱导局部贪心选错的分支；深度 12 的多配方 Fibonacci DAG，用最小叶子需求前沿校验结果。
- 环裁切：`A <-> 9B` 与 `B <-> 9C` 的换算环；`A -> 2A` 自增环。自增是正收益闭环，不要求普通规划器完成，只验证安全裁切且不产生 firing。
- 催化剂：直接归还的普通催化剂；原始守恒反馈图 `A -> 2B, 2B+C -> E+D, D -> A`；以及递减反馈图 `3A -> 2B, 2B -> D+2A`。后两者直接交给 Thunderbolt，测试其自动归一化、启动种子约束和执行结果，不使用天枢 closed-loop，也不在测试中手工缩点。递减图每个 `D` 净消耗一个 `A`，此外还需保留两个 `A` 作为启动状态，因此 `N` 个 `D` 的最低初始材料为 `N+2` 个 `A`。
- 耐久链：一件工具可使用 100 次，规划 10000 个产物，校验有限使用次数。
- 模糊样板：逻辑工具可路由到实际的受损工具，并作为可复用材料归还。

默认单次 `check` 或规划时限为 1 秒，超时取消宽限为 100 毫秒。它是参考能力边界；作者可用同一套图调整规模并另外声明自己的能力范围，但不得把较小规模结果冒充本套件结果。

## Thunderbolt V2 当前基线

`ThunderboltReferenceCapabilitySuiteTest` 将已确认的当前限制显式列在 `EXPECTED_LIMITATIONS` 中。当前列表为空，33 个材料用例都必须返回 `SUPPORTED`。

`catalyst/raw-feedback-loop` 和 `catalyst/lossy-feedback-loop` 都走 Thunderbolt 的原始图入口，不是天枢 closed-loop 用例。规划器会在代数/DP 阶段之前分析包含主产物和副产物边的 SCC；只有每个参与样板都可证明为“一个内部状态输入到一个内部状态输出”，并且每个内部状态都不增殖的反馈环才进入普通反馈路径。逐状态完全守恒时只校验真实启动 seed；存在递减时，逐轮净损耗进入普通材料消耗，环末仍需保留的状态单独计入启动储备。正收益自增环仍不进入这条路径。

后续一旦出现已确认且暂时不能修复的限制，应按具体用例 ID 加入该表；其他任何非 `SUPPORTED` 结果都会失败，不能用宽泛基线掩盖测试建模错误。

缺失量质量中，当前多配方 Fibonacci 缺失用例会返回有效但非最小的集合，控制台中的 `missingOverhead` 用于量化偏差；这不改变其结果正确性分类。
